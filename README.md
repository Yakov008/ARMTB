# Удалённое открытие шкафа с тормозными башмаками

Поездной диспетчер (ДНЦ) нажимает «Открыть» в программе, и на станции без дежурного
(ДСП) открывается электромеханический замок шкафа. Локомотивная бригада берёт башмаки,
закрывает дверь, и шкаф запирается сам. Каждое действие записывается в журнал.

## Как это работает

```
 ┌──────────────────────── ПОСТ ЭЦ / СТАНЦИЯ ────────────────────────┐
 │                                                                   │
 │  Шкаф ТБ                                                          │
 │  ┌──────────────┐   GPIO26   ┌───────┐  12 В  ┌─────────────────┐  │
 │  │    ESP32     ├───────────►│ Реле/ ├───────►│ Электромех.     │  │
 │  │ (контроллер) │            │MOSFET │        │ замок           │  │
 │  │              │◄───────────┤       │        └─────────────────┘  │
 │  │              │   GPIO27   ┌───────┐                             │
 │  │              │◄───────────┤Геркон │  датчик «дверь открыта»     │
 │  └──────┬───────┘            └───────┘                             │
 │         │ Wi-Fi                                                    │
 │  ┌──────▼───────┐                                                  │
 │  │ Роутер 4G/   │   (или кабель в сеть передачи данных дороги)     │
 │  │ Wi-Fi        │                                                  │
 │  └──────┬───────┘                                                  │
 └─────────┼──────────────────────────────────────────────────────────┘
           │  Интернет / VPN / СПД ОТН
           │  WebSocket: шкаф САМ подключается к серверу и держит канал
           ▼
 ┌──────────────────────┐        браузер         ┌──────────────────┐
 │  LockServer.exe      │◄──────────────────────►│ АРМ ДНЦ          │
 │  (сервер + журнал)   │   http://сервер:8000   │ кнопки Открыть / │
 │  events.db           │                        │ Закрыть, журнал  │
 └──────────────────────┘                        └──────────────────┘
```

### Сценарий закрепления

1. Бригада по радиосвязи просит ДНЦ дать доступ к башмакам.
2. ДНЦ в программе нажимает **«Открыть»** у нужного шкафа и указывает номер поезда.
3. Сервер передаёт шкафу команду `open`, шкаф подтверждает её. Если подтверждения
   нет, ДНЦ сразу видит ошибку «Шкаф не подтвердил команду».
4. ESP32 включает реле, и замок открывается. На экране ДНЦ: «🔓 Открыт».
5. Бригада открывает дверь (геркон фиксирует «Дверь открыта»), берёт башмаки и
   закрывает дверь.
6. Через 1 с после закрытия двери замок запирается автоматически: «🔒 Закрыт».
   - Если дверь не открыли за 60 с, замок закрывается сам.
   - Если дверь открыта дольше 10 минут, контроллер всё равно снимает питание с замка.
   - ДНЦ может закрыть шкаф вручную кнопкой **«Закрыть»**.
7. Если дверь открыли без команды (механическим ключом или взломом), у ДНЦ появляется
   тревога «⚠ Дверь открыта без команды».
8. Журнал хранит, кто открыл, когда, для какого поезда, когда открыли и закрыли дверь.

### Почему шкаф сам подключается к серверу

На станции обычно нет постоянного внешнего IP-адреса. Поэтому ESP32 сам устанавливает
исходящее WebSocket-соединение с сервером и держит его открытым. Команды приходят по
этому каналу мгновенно. Пробрасывать порты на станции не нужно. Если связь пропала,
ESP32 переподключается каждые 5 с, а на сервере через ~35 с шкаф отображается как
«Нет связи».

## Состав проекта

| Папка | Что это |
|---|---|
| `firmware/shoebox_lock/` | Прошивка ESP32 (Arduino). Все настройки в `config.h` |
| `server/app.py` | Сервер: API, WebSocket для шкафов и интерфейса, журнал SQLite |
| `server/static/index.html` | Веб-интерфейс диспетчера |
| `bin/LockServer.exe` | Готовая программа для Windows (Python не нужен) |
| `server/build_exe.bat` | Пересборка exe после изменений в коде |
| `simulator/device_sim.py` | Эмулятор шкафа для проверки без железа |

## Оборудование на один шкаф

| Компонент | Пример | Примечание |
|---|---|---|
| Контроллер | ESP32-DevKitC (WROOM-32) | Wi-Fi есть на плате |
| Замок | Электромеханический 12 В, нормально закрытый (fail-secure) | Без питания остаётся закрытым, есть механический ключ |
| Ключ питания замка | Модуль реле 5 В или MOSFET IRLZ44N + диод 1N4007 | Для MOSFET обязателен диод параллельно замку |
| Датчик двери | Геркон (магнитоконтакт) СМК / ИО-102 | Магнит на двери, геркон на корпусе |
| Питание | Блок 12 В 2 А + понижающий DC-DC 12→5 В | Для ESP32 |
| Резерв | Аккумулятор 12 В 7 А·ч + блок бесперебойного питания (ББП) | Работа при отключении сети |
| Связь | 4G-роутер или Wi-Fi точка на посту ЭЦ | Либо Ethernet-модуль W5500 |
| Корпус | Щиток IP54/IP65 | Шкаф стоит на улице или в неотапливаемом помещении |

### Подключение

```
ESP32 GPIO26 ──► IN реле (или затвор MOSFET через 100 Ом)
ESP32 GND    ──► GND реле
ESP32 GPIO27 ──► геркон ──► GND          (подтяжка внутри ESP32)
ESP32 5V/VIN ◄── DC-DC 12→5 В

Цепь замка (реле):  +12 В ─► COM реле, NO реле ─► «+» замка, «−» замка ─► −12 В
```

> **Магнитный замок, как в домофоне** (электромагнит), открывается при пропадании
> питания. Если поставите его, укажите `LOCK_FAIL_SECURE false` в `config.h`.
> Для шкафа с башмаками лучше электромеханический замок: при отключении питания он
> остаётся закрытым, а открыть его можно механическим ключом.

## Запуск

### 1. Проверка без железа (5 минут)

1. Запустите `bin\LockServer.exe`. В консоли будет пароль пользователя `admin`,
   а в браузере откроется `http://localhost:8000`.
2. В другом окне запустите эмулятор шкафа (нужен Python и `pip install websockets`):
   ```bash
   python simulator/device_sim.py korshuniha-1 secret-token-korshuniha-1
   ```
3. Войдите как `admin` и нажмите «Открыть». В эмуляторе появится `>>> РЕЛЕ: замок ОТКРЫТ`.
4. В окне эмулятора наберите `o` и Enter (дверь открыта), затем `c` и Enter (дверь
   закрыта). Замок закроется сам, а в журнале появятся все шаги.

### 2. Настройка сервера

Файлы рядом с `LockServer.exe` создаются при первом запуске:

- **`devices.json`**: список шкафов. Для каждого задайте свой длинный случайный `token`:
  ```json
  {"devices": [
    {"id": "korshuniha-1", "name": "Коршуниха-Ангарская, шкаф №1", "token": "длинный-случайный-токен"}
  ]}
  ```
- **`users.json`**: диспетчеры. Пароли хранятся в виде хэшей. Добавить диспетчера:
  `python app.py adduser ivanov` (из папки `server`).
- **`events.db`**: журнал событий (SQLite).

Сервер слушает порт 8000 на всех сетевых интерфейсах. Другие компьютеры ДНЦ
открывают `http://<IP-сервера>:8000`. Порт можно сменить переменной окружения
`LOCK_PORT`. В брандмауэре Windows нужно разрешить входящие подключения на этот порт.

### 3. Прошивка ESP32

1. Установите Arduino IDE 2.x и поддержку плат ESP32: Boards Manager → «esp32 by Espressif».
2. В Library Manager установите **WebSockets** (Markus Sattler) и **ArduinoJson** (v7).
3. Откройте `firmware/shoebox_lock/shoebox_lock.ino` и заполните `config.h`:
   Wi-Fi, IP сервера, `DEVICE_ID` и `DEVICE_TOKEN` (те же, что в `devices.json`).
4. Выберите плату «ESP32 Dev Module» и порт, затем нажмите «Загрузить».
5. В мониторе порта (115200) должно появиться `[ws] connected`, а у ДНЦ: «На связи».

Светодиод на плате горит постоянно, когда связь есть, и мигает, когда её нет.

## Безопасность (обязательно до реальной эксплуатации)

- **Шифрование канала.** Сейчас используется `ws://` без шифрования, этого достаточно
  для стенда. В эксплуатации нужен один из двух вариантов: закрытая сеть (VPN в
  4G-роутере или СПД дороги) либо `wss://` (TLS) через обратный прокси, например nginx
  или Caddy с сертификатом, и `USE_TLS true` в `config.h`.
- **Токены.** У каждого шкафа должен быть свой токен. Подключение с чужим токеном
  отклоняется и попадает в журнал как «⚠ Чужое устройство».
- **Пароли.** Пароль `admin` нужно сменить, а каждому ДНЦ завести свою учётную запись,
  чтобы в журнале было видно, кто открывал шкаф.
- **Отказ связи или питания.** Шкаф остаётся закрытым, бригада открывает его резервным
  механическим ключом, а открытие двери без команды фиксируется в журнале.

## Что можно добавить

- Датчики наличия башмаков: RFID-метки на каждом башмаке или концевики в ячейках.
  Тогда ДНЦ будет видеть, сколько башмаков взяли и вернули.
- Кнопку вызова ДНЦ и IP-камеру на шкафу для идентификации бригады.
- Telegram-бот или SMS-уведомления о тревогах.
- Связь через Ethernet (W5500) или GSM-модем вместо Wi-Fi.
